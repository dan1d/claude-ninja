# /init — claude-ninja project initialization

Scan the current project, read existing documentation, and generate a developer-focused Obsidian vault scaffold with architecture summary, Dev Tracker, and decision log.

**Arguments:** $ARGUMENTS

## Instructions

### 1. Detect project identity

```bash
# Check for existing obsidian-project config
cat .claude/obsidian-project 2>/dev/null
```

If `.claude/obsidian-project` exists, use that name. Otherwise:
- Use `$ARGUMENTS` if provided (e.g., `/init biobridge`)
- Fall back to `basename $(pwd)`

Store the result as `PROJECT_NAME`.

### 2. Check Obsidian vault

```bash
echo "${OBSIDIAN_VAULT:-not set}"
```

If `$OBSIDIAN_VAULT` is not set, tell the user:
> OBSIDIAN_VAULT is not set. Run: `export OBSIDIAN_VAULT="$HOME/Documents/obsidian/YourVaultName"`

If the vault directory does not exist, warn and ask whether to proceed (files will be created locally in `.claude/docs/` instead).

### 3. Scan for existing documentation

Search the project root and one level of sub-directories for documentation files:

```bash
# Root-level docs
find . -maxdepth 1 -name '*.md' -not -name 'CHANGELOG*' -not -name 'LICENSE*' | sort

# docs/ directory
find ./docs -name '*.md' 2>/dev/null | sort

# Sub-project CLAUDE.md / README.md (monorepo detection)
find . -mindepth 2 -maxdepth 2 -name 'CLAUDE.md' -o -name 'README.md' -o -name '*.md' -path '*/docs/*' 2>/dev/null | head -20

# Sub-project detection
find . -mindepth 1 -maxdepth 1 -type d -not -name '.*' -not -name 'node_modules' -not -name 'vendor' -not -name 'tmp' | sort
```

Read each discovered file. Build an index:
- `CLAUDE.md` or project root `.md` → project context
- `docs/*.md` → domain documentation
- Sub-directories with their own `CLAUDE.md`, `package.json`, `Gemfile`, or `go.mod` → sub-projects in a monorepo

### 4. Detect project type

Based on what you found, classify:

| Signal | Type |
|--------|------|
| Multiple sub-dirs with their own package.json/Gemfile | **Monorepo** |
| Single package.json or Gemfile at root | **Single project** |
| Multiple git repos under one parent dir | **Multi-repo workspace** (like biobridge) |

For monorepos and multi-repo workspaces, list each sub-project with its stack.

### 5. Generate Architecture.md

Synthesize a developer-focused architecture document from ALL the docs you read. This is the key output — it should let a new developer understand the project in 5 minutes.

Structure:

```markdown
# {PROJECT_NAME} — Architecture

> Auto-generated by claude-ninja /init on {date}. Edit freely — this is your reference doc.

## Overview
{1-2 paragraphs: what the project does, who uses it, what problem it solves}

## Stack
| Component | Technology |
|-----------|-----------|
{table of stack components from docs}

## Repository Structure
{For monorepo/multi-repo: table of sub-projects with stack and purpose}
{For single project: key directory layout}

## How to Run
{Dev setup commands extracted from README/CLAUDE.md/docs}

## Key Patterns
{Important architectural patterns, conventions, and gotchas extracted from docs}
- {e.g., "Service objects in app/services/ — one public method per class"}
- {e.g., "Auth via Auth0 + macaroon tokens"}
- {e.g., "Background jobs on Sidekiq — always idempotent"}

## Domain Model
{Key entities and their relationships, extracted from business docs if available}

## API / Integration Points
{External services, APIs, webhooks — extracted from docs}

## Testing
{Testing stack, how to run tests, key patterns — extracted from testing docs}
```

**Important:** Do NOT copy-paste entire doc files. Synthesize and compress. Link back to source files for details:
> For full service catalog, see `docs/services.md`

### 6. Generate Dev Tracker

```markdown
# {PROJECT_NAME} — Dev Tracker

## In Progress

## Up Next

## Completed
```

### 7. Generate supporting files

**Decisions.md:**
```markdown
# {PROJECT_NAME} — Decisions

Append-only log of architectural and technical decisions.

---

## Template

### {YYYY-MM-DD} — {Decision Title}
**Context:** {What prompted this decision}
**Decision:** {What we chose}
**Alternatives:** {What we considered}
**Why:** {Why this option won}
```

**Known Issues.md:**
```markdown
# {PROJECT_NAME} — Known Issues

Bugs, tech debt, and gotchas. Updated by claude-ninja judges and manual entries.

---
```

### 8. Write files to Obsidian vault

Write all generated files to `$OBSIDIAN_VAULT/{PROJECT_NAME}/`:

```
{PROJECT_NAME}/
├── Architecture.md          ← synthesized from project docs
├── Decisions.md             ← empty template
├── Known Issues.md          ← empty template
└── Dev/
    └── Dev Tracker.md       ← empty tracker (required for hooks)
```

**Skip any file that already exists** — never overwrite the user's notes.

### 9. Set up .claude/obsidian-project

If `.claude/obsidian-project` does not exist:

```bash
mkdir -p .claude
echo '{PROJECT_NAME}' > .claude/obsidian-project
```

Tell the user:
> ✓ Obsidian vault scaffold created at `$OBSIDIAN_VAULT/{PROJECT_NAME}/`
> ✓ `.claude/obsidian-project` set to `{PROJECT_NAME}`
>
> The Dev Tracker is ready — claude-ninja hooks will now track your tasks.
> Architecture.md was synthesized from {N} documentation files.
>
> **Next steps:**
> - Review Architecture.md and edit anything that's wrong
> - Start working — the task gate will prompt you to plan in the Dev Tracker

### 10. For multi-repo workspaces

If the project is a multi-repo workspace (like biobridge), also:
- Offer to set `.claude/obsidian-project` in each sub-project pointing to the same vault project name
- Note in the output: "Sub-projects can share this vault — set `echo '{PROJECT_NAME}' > .claude/obsidian-project` in each repo"
